Nội dung 3 bullet:
1. Internet hiện đại không còn end-to-end: request đi qua nhiều middlebox (proxy, CDN, WAF, app server).

2.1 HTTP, CGI, AND REQUEST SMUGGLING (2 slides — 1.5 phút)

Slide 3 — HTTP/1.1 và CGI cơ bản

Tạo slide background về HTTP/1.1 và CGI.
Tiêu đề: "HTTP/1.1 — Hai tính năng then chốt gây ra Desync"
Layout 2 cột:
Cột trái — Persistent Connection & Pipelining:
- Một TCP connection chứa NHIỀU HTTP messages liên tiếp.
- Server phải xác định ranh giới giữa các message bằng Content-Length hoặc Transfer-Encoding: chunked.
Cột phải — CGI và biến thể:
- CGI là cầu nối giữa web server và application.
- WSGI (Python), FastCGI (PHP), AJP (Tomcat), uwsgi — đều là biến thể CGI.
- Mỗi gateway lại parse HTTP/CGI hơi khác nhau.
Dưới cùng có dòng: "Vì sao quan trọng: ranh giới message + chuyển đổi protocol = 2 nguồn discrepancy chính."

4.1 WORKFLOW (1 slide — 1 phút)

Slide 8 — HDHUNTER Workflow (7 bước)

Tạo slide workflow tổng thể của HDHUNTER.
Tiêu đề: "HDHUNTER Workflow"
Sơ đồ vòng tròn 7 bước (mỗi bước 1 node, có mũi tên kết nối):
1. Seed Collection (manual capture từ traffic thật)
2. Corpus — fuzzer chọn 1 test case
3. Mutator — biến đổi (sequence/message/byte)
4. Executor — chạy trên 2 implementations song song, thu COVERAGE + STATES
5. Detector — so sánh State Tuple, ghi discrepancy nếu có
6. Feedback — input nào kích hoạt edge mới mà KHÔNG gây discrepancy → giữ lại corpus
7. Manual analysis → vulnerability
Lưu ý visual: bước 4-5-6 nằm trong "main loop" có background màu nhạt.
Ghi chú dưới: "AFL-like framework, but extended for multi-target differential testing."

4.2.1 STRUCTURE OF TEST CASE (1 slide — 45s)

Slide 9 — Test Case Structure: Cây cấu trúc thay vì byte stream

Tạo slide cấu trúc test case của HDHUNTER.
Tiêu đề: "Test Case Structure — Vì sao không fuzz byte ngẫu nhiên?"
Bên trái — sơ đồ cây:
TestCase (array of messages)
 └── HTTP Message
      ├── Start-line (Method + URI + Version)  hoặc (Version + Status + Reason)  hoặc (Status header cho CGI)
      ├── Field-lines (headers, mỗi header có name/value/datatype: string/number/symbol)
      └── Message-body (raw OR chunked)
Bên phải — bullet:
- Tree-based structure theo ABNF của RFC.
- Mỗi field có DATATYPE (string/number/symbol) → guide mutator chọn chiến lược phù hợp.
- 1 cấu trúc duy nhất phục vụ cả HTTP Request, HTTP Response, CGI Response.
Note nhỏ: "CGI status code nằm trong header 'Status:' chứ không phải start-line."
